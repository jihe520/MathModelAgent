# 桌面版国赛 AI 工具使用详情集成设计

日期：2026-08-24  
范围：桌面版内置的 MathModelAgent Skills 工作流

## 1. 背景与边界

仓库 README 说明桌面版内置 Claude Code 与全套 MathModelAgent Skills，但当前仓库不包含 Electron、Tauri 或其他桌面壳及其打包源码。因此，本次改动以桌面版实际使用的 Skills 工作流为集成边界，不修改仓库中的旧 Vue/FastAPI 工作流，也不声称能够直接更新已经发布或安装的桌面程序。

原作者合并本改动并重新打包桌面版后，新版桌面程序才能包含该功能。

## 2. 目标

当用户在桌面版中启动全国大学生数学建模竞赛（国赛，CUMCM）论文生成任务时：

1. 主工作流自动启用 `7ai-disclosure`。
2. 从任务开始持续记录实际使用的 AI 工具、模型、用途、提示过程、输出采纳与核验情况。
3. 完整论文通过验收后，只向队员集中询问一次必须由人确认的信息。
4. 确认完成后生成名称完全一致的 `AI 工具使用详情.pdf`。
5. `paper/main.pdf` 与该支撑材料 PDF 均通过验收后，任务才能报告最终完成。

## 3. 非目标

- 不为美赛或其他赛事强制生成国赛支撑材料。
- 不修改已经发布的桌面安装包。
- 不在缺少真实证据时推测或编造人工修改、人工核验情况。
- 不把 API Key、访问令牌、完整敏感提示或内部调试信息写入最终 PDF。
- 不把空白模板作为成功产物。

## 4. 方案

采用 Skill 工作流内的确定性集成，不依赖模型自行记住赛后补写材料。

```text
国赛任务启动
  -> 1start-mathmodel 初始化 AI_USAGE_LOG.md
  -> 各工作阶段结束后调用 7ai-disclosure record
  -> 5writing 生成完整论文
  -> 6verity 验收论文和项目产物
  -> 7ai-disclosure 汇总一次性人工确认问题
  -> 队员回复一次
  -> 7ai-disclosure finalize 生成并检查 PDF
  -> 论文 PDF + AI 工具使用详情.pdf 均通过后报告完成
```

## 5. 启用条件

`1start-mathmodel` 根据任务明确选择的赛事模板或题目信息判断赛事：

- `CHINA`、`国赛`、`CUMCM` 或“全国大学生数学建模竞赛”视为国赛任务，必须启用 `7ai-disclosure`。
- 明确为其他赛事时不启用该国赛支撑材料流程。
- 无法判断赛事时，在任务开始阶段询问赛事类型；不得等到论文完成后再判断。

如果队伍确认全程未使用任何 AI，不生成空白 PDF，并在验收报告中保存该确认。桌面 Agent 本身参与了论文生成时，不得使用“全程未使用 AI”分支。

## 6. 记录机制

### 6.1 初始化

国赛工作流开始时，从模板创建 `reports/AI_USAGE_LOG.md`。日志使用稳定工具编号 `T1`、`T2` 等，使后续用途、提示过程和采纳核验记录能够对应具体工具。

工具名称与模型优先读取任务的真实运行配置和模型响应元数据；无法获得的字段进入最终一次性确认清单，不能自行猜测版本。

### 6.2 阶段记录

以下阶段结束后立即执行 `7ai-disclosure record`：

- 赛题分析与任务拆解；
- 建模与方法选择；
- 代码生成、调试和计算；
- 图表与流程图生成；
- 论文写作与排版；
- 论文和项目验收。

每条记录至少包含工具编号、使用环节、具体目的、提示方式或提示摘要、AI 输出去向、已完成的修改和核验证据。记录只能来自本次任务的真实输入、对话、代码、结果和文件，不允许赛后凭空补造。

### 6.3 一次性人工确认

完成论文验收后，`7ai-disclosure` 汇总所有仍需人确认的内容，以一条消息集中询问。确认内容主要包括：

- 队员是否采纳相关 AI 输出；
- 做过哪些非语言润色类人工修改；
- 使用什么方式人工核验关键结果；
- 无法从运行元数据确定的工具版本或型号。

队员只需回复一次。最终生成器把回复写入日志并重新校验；回复仍有缺项时，明确指出缺失项并停止生成，不输出带占位符的提交版 PDF。

## 7. PDF 生成

`7ai-disclosure finalize` 调用仓库内的确定性生成脚本，而不是仅依靠模型自由编辑模板。生成器负责：

1. 解析并校验 `reports/AI_USAGE_LOG.md`。
2. 将日志映射到既定四部分模板。
3. 对插入 LaTeX 的动态内容进行转义。
4. 写出 `supporting_materials/AI 工具使用详情.tex`。
5. 优先使用 XeLaTeX 编译两遍；XeLaTeX 不可用时回退到 Tectonic。两者均不可用或编译失败时停止生成。
6. 生成 `supporting_materials/AI 工具使用详情.pdf`。
7. 检查文件非空、文件名完全一致、页面为 A4、存在文本层、四个部分齐全，且不含占位符或疑似密钥。

生成后的 PDF 保持当前已经确认的简洁四部分结构与版式，不增加责任说明、基本信息、最终确认或其他已删除章节。

## 8. 工作流门禁与错误处理

以下任一情况发生时，国赛任务不得报告最终完成：

- `7ai-disclosure` 未被安装或无法加载；
- AI 使用日志缺失、字段不完整或仍有待确认内容；
- 一次性人工确认尚未完成；
- PDF 编译器不可用或编译失败；
- 最终文件名不完全等于 `AI 工具使用详情.pdf`；
- PDF 为空、不是 A4、没有文本层、缺少规定部分；
- PDF 含占位符、密钥或未经确认的陈述；
- `paper/main.pdf` 或 AI 支撑材料 PDF 任一缺失。

错误消息应说明失败环节、缺失内容和恢复方式。用户修正后从失败环节继续，不重复已经完成的建模与论文生成。

## 9. 仓库改动点

- `skills/skills.sh.json`：把 `7ai-disclosure` 加入工作流 Skill 清单。
- `skills/1start-mathmodel/SKILL.md`：明确国赛触发、阶段记录、一次确认、最终双文件门禁。
- `skills/6verity/SKILL.md`：把 AI 支撑材料纳入国赛最终验收。
- `skills/7ai-disclosure/SKILL.md`：定义自动记录、一次确认和确定性生成流程。
- `skills/7ai-disclosure/scripts/`：增加确定性 PDF 生成及必要的校验逻辑。
- `skills/doctor/SKILL.md`：检查 `7ai-disclosure`、Python，以及 XeLaTeX 或 Tectonic PDF 编译依赖。
- `README.md`、`README_EN.md`：说明国赛任务会同时生成 AI 使用详情，以及人工确认门禁。

不修改 `backend/` 与 `frontend/`；它们不是 README 所述桌面版的打包源码。

## 10. 测试与验收

至少覆盖以下自动测试：

1. 国赛任务会初始化日志并进入披露流程。
2. 非国赛任务不会生成国赛支撑材料。
3. 存在待确认内容时，生成器拒绝输出提交版 PDF。
4. 一次确认完成后，日志通过最终校验。
5. 多个 AI 工具的编号能在四部分之间正确对应。
6. 特殊字符不会破坏 LaTeX 编译。
7. 模拟编译失败时，最终门禁失败并给出恢复提示。
8. 成功样例生成名称准确的 A4 PDF，具有文本层和四个规定部分。
9. 输出不包含占位符、疑似密钥和模板提示。
10. `paper/main.pdf` 存在但 AI 支撑材料缺失时，国赛任务不能报告最终完成。

最终还需用一个最小国赛夹具执行端到端测试，确认输出目录同时包含 `paper/main.pdf` 和 `supporting_materials/AI 工具使用详情.pdf`。

## 11. 完成标准

本功能完成需同时满足：

- `7ai-disclosure` 可被桌面 Skill 安装和发现；
- 国赛主工作流自动调用该 Skill；
- 人工信息只集中确认一次；
- 最终 PDF 由真实日志确定性生成并通过检查；
- 缺少该 PDF 时国赛任务不能显示最终成功；
- 自动测试和最小端到端测试均通过；
- 工作区不存在未说明的生成物或敏感信息。
