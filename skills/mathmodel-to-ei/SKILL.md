# 数模论文转 EI 会议论文

将完整数模论文转换成一篇证据可追溯、研究主线清楚的英文会议稿。默认使用内置 IEEE 模板；不将“套模板”或“英文翻译”当作完成转换，也不承诺录用或 EI 收录。

## 输入与默认选择

**唯一必需输入：一篇完整数模论文**，可以是 PDF、Word 或 LaTeX 项目。包含正文、公式、结果、图表与参考文献；附件缺失不自动意味着论文不完整。仅有题目、摘要或提纲时，先要求提供完整论文，不从零补造研究。

可选：代码与数据、原始图件、目标会议及征稿链接、页数/语言要求、作者单位、匿名要求。先检查用户提供的路径和附件，避免重复索要已有信息。

- 没有目标会议：继续制作通用英文 IEEE conference 初稿，记录“目标会议待定”，不假定 6 页或规定图数。
- 只有论文：正常改写；数值注明来源于原稿，不声称复现。PDF 抽取失败时尝试可用的版面读取/OCR，关键公式和表格必须对照原页。
- 有代码/数据：按主要结论选择必要的复核或重算；未经请求不扩展成大规模新实验项目。缺少证据的结论降级、删除或列为待验证，不能用编造数值补齐。
- 作者信息缺失：使用明确的作者占位并列入待办；匿名审稿按会议要求处理，不凭空填作者、单位或基金。
- 目标会议有自己的模板：优先用户提供的目标模板，保留本技能的改写流程。IEEE 不是所有 EI 会议的通用格式。

## 工作流程

### 1. 通读和确定研究主线

读取原稿、项目说明和适用的 AGENTS.md，查看现有结果及图表。识别实际研究领域，不根据“竞赛 A/C 题”等编号猜测主题。

选取原稿中证据最充分、能形成连贯贡献的研究问题。多个竞赛小问可以合并，也可以只保留必要部分；不要逐个照搬“问题一、问题二、问题三”。在改稿说明中写清研究问题、方法、可支持的贡献和范围。常规算法的组合不能直接包装为首创。

### 2. 建立证据和图表清单

改写前阅读 [改写与核验指南](references/conversion-guide.md)。在输出目录保存 `改稿说明.md`，随着工作更新：

- 原章节到会议稿章节的映射及重要删改理由；
- 核心结论、原始位置、数值来源、核验状态；
- 原图/原表到新稿的去向，删除、合并、重绘的理由；
- 数据性质、实验边界、缺失信息与投稿前待办。

区分真实测量、官方数据、仿真数据、合成数据及示意图。不能把原稿的假设换成“真实数据”，也不能把模拟器结果写成硬件实测。

### 3. 建立独立 LaTeX 输出项目

保留原稿，默认在论文项目旁或项目内新建 `conference_ieee/`。已有转换稿则在用户指定版本上继续修改，不覆盖别的项目。

首次创建可执行（`SKILL_DIR` 表示当前技能目录，使用实际绝对路径）：

```bash
python3 "SKILL_DIR/scripts/init_manuscript.py" --output "/absolute/path/conference_ieee"
```

脚本仅复制内置模板并建立图件与验证目录；拒绝覆盖已有目录。**初始化的 `main.tex` 是模板范例，必须替换其示例正文、作者、参考文献和示例图片，才能成为论文。** 模板来源、文件和适用范围见 [模板说明](references/template.md)。

### 4. 改写论文和整理图表

围绕问题、方法和证据组织英文稿。通常包含 Introduction、Related Work、Problem Formulation、Method、Experiments and Results、Conclusion；按实际研究合并或调整，不强制每稿完全相同。

保留影响复现的变量定义、约束、算法细节、参数和实验设置。摘要的数字须与结果表一致；结论不超出实验。移除竞赛题面复述、组织口号和与主线无关的答题内容。

图表按其论证用途选择：方法机制、主要结果、解释原因、适用边界。不要为了凑页数或图数删掉必要证据。重绘时优先复用真实数据和可执行绘图代码；只有原图时保留清晰可读版本或忠实重绘，不能猜出精确数据。每幅图有英文图注、正文引用、单位及可追溯来源。科学结果图使用常规绘图工具，不用生成式图片模拟曲线或实验结果。

如需补文献或核实引用，检索原始论文、出版商或会议官方页面；不编造 DOI、页码、会议名称与参考文献。用户要求选会或判断 EI 收录时，另行核实当前官方信息，并说明已核实的范围。

### 5. 编译、检查、交付

保持模板的字号、栏宽和页边距；页数限制以明确会议要求或用户要求为准。超页优先改内容和图表布局，不用极端缩字号或负间距掩盖。

在支持的环境中打开 `main.tex` 到内置 LaTeX 编辑器并调用编译工具，按其限制修复。多文件或外部图件不受支持时，保留编辑器和源码，使用已有完整项目编译器验证；不要把预览打开当作编译成功，也不要为内置编辑器安装 TeX。

已有本地工具时，可在输出目录使用：

```bash
latexmk -pdf -interaction=nonstopmode -halt-on-error -file-line-error main.tex
```

按实际编译器/字体要求调整命令。检查引用、交叉引用、公式、所有关键数值及字体/边界警告，并逐页检查 PDF 的图表清晰度、裁切、浮动位置和空白。实际无法编译时交付源码并明确原因，不宣称 PDF 已验证。可用完整编译器时，最终源码包在独立目录解压编译一次，确认没有绝对路径依赖或遗漏图件。

通常交付：

- `main.tex`、必要的类文件、参考文献和图件；
- 实际编译成功的 `main.pdf`；
- `改稿说明.md`，含图表取舍、证据状态和未完成的投稿信息；
- 必要的绘图脚本/数据及 `validation/` 中简短的验证记录；
- 可独立编译的源码 ZIP，不混入原始敏感数据、无用缓存或机器专属环境。

完成改稿与本地交付无需额外审批；不因缺少非必需信息停止可完成的工作。本技能不包含投稿、支付版面费或联系作者/会议。
